# 一起听

「一起听」让多个 LX Music 客户端进入同一个虚拟房间，由房主控制播放，房间内所有人的歌曲、播放/暂停状态和进度保持同步。

这是一个**自建服务**的功能：需要先运行项目内的中继服务端 `listen-together-server`，客户端再填写服务端地址。

## 使用方式

> 已部署一个可直接用的公网实例（平台托管，长期使用可按下文自建，见 `listen-together-server/DEPLOY.md`）：
> - App 服务器地址（已内置，可在设置里改）：`wss://af384ee6deb6e09e2.app.workbuddy.host?sharecode=MKPWEVLBUS`
> - 网页版（已内置，可在设置里改）：https://af384ee6deb6e09e2.app.workbuddy.host/?sharecode=MKPWEVLBUS （浏览器打开，填昵称 + 房间码即可加入）

1. 在一台能被手机访问的机器上启动服务端：

   ```bash
   cd listen-together-server
   npm install
   npm start
   ```

   服务端会打印局域网地址，例如 `ws://192.168.1.10:23333`。

2. 打开 App，进入「我的 → 设置 → 其他 → 一起听」，填写服务器地址并保存。

3. 也可以直接从播放详情页右上角的「一起听」按钮进入。

4. 房主：填写昵称后点击「创建房间」，把 6 位房间码发给好友。
   成员：填写昵称和房间码后点击「加入房间」。

5. 房主在播放详情页正常播放、暂停、切歌、拖动进度，房间内其他成员会自动跟随。

## 房间内可以做什么

- 查看房间码、成员列表和当前播放的歌曲/进度。
- 文字聊天（含成员加入、离开、房主变更等系统消息）。
- 房主可以点选其他成员，把房主转交给他。
- 任意成员可以随时退出房间，退出后不再跟随房间播放。

## 同步规则（1.12.0 更新）

- **房主权威**：只有房主的播放状态会广播到房间。
- **成员播放源（1.13.0）**：房间空闲（还没有任何播放状态）时，成员播放歌曲即成为播放源，网页端和其它成员全部跟随（歌曲、进度、歌词、音频直链）；房主开始播放后自动收回播放源，播放源退出时房间回到等待状态。1.13.1 修复：播放源成员切歌后本端未认领身份导致不同步——服务端现在会把 `state`/`lyric` 回显给发送者本人，App 端广播成功后也会在本地认领播放源身份。
- **成员也能控制播放**：成员的播放/暂停/拖动进度会通过 `control` 消息转给房主执行（`handleControl`），房主执行后再统一广播，所有端保持一致；成员端刚跟随过房主的状态时 1.2 秒内不会把播放器自己的变化当成用户操作回传，避免循环。
- **房间统一音质**：房主的播放音质随播放状态（`quality` 字段）下发，成员取播放地址时按房间音质（`src/core/music/online.ts` 的 `qualityOverride`），不受自己本地音质设置影响；退出房间后恢复。
- **状态广播**：房主在切歌、播放/暂停、拖动进度时立即广播；此外每 4 秒广播一次心跳状态，用于校正进度漂移。
- **漂移校正**：成员端与目标进度的偏差超过 1.5 秒时自动 seek。
- **歌词同步**：房主解析出歌词后通过 `lyric` 消息推给房间（服务端保存一份，后加入的成员在 `room` 消息里直接拿到）；成员端锁定这份歌词（`core/lyric.ts` 的 `setLockedLyric`），本地歌词加载完成也不会覆盖，保证两端同一秒唱同一句。按「音源+歌曲 id」匹配，匹配不上时按「歌名+歌手」兜底。网页版同样按时间轴滚动显示当前句。
- **歌曲解析**：
  - 在线歌曲会携带完整的歌曲信息，成员端直接用自己的音源取播放地址。
  - 本地歌曲（或音源不可用）会在成员端按歌名、歌手、时长搜索同名歌曲，找到后播放。
  - 都找不到时，成员端会提示「未找到可播放的歌曲」，房主和其他成员不受影响。
- **断线重连**：连接断开后自动重连（最长 8 次，指数退避）。重连时携带成员凭证，可恢复原成员身份；房主掉线后有 20 秒宽限期，期间重连可保留房主身份。

## 数据流

```
房主播放器状态
   │  state_event: playMusicInfoChanged / playStateChanged / playProgressChanged
   ▼
playerSync.broadcastState()  ──►  WebSocket  ──►  中继服务端
                                                    │ 校验房主身份、规范化状态
                                                    ▼
                                        广播给房间内其他成员
                                                    │
成员端 applyRemoteState() ◄──────────────────────────┘
   │  歌曲不同 → 解析歌曲并播放 → 等待加载完成后 seek
   │  歌曲相同 → 播放/暂停 + 进度校正
   ▼
成员播放器
```

## 网页版音频同步

房主广播的 `PlaybackState.music` 里带一个 `url` 字段（`src/core/listenTogether/playerSync.ts`）：

```ts
interface MusicSnapshot {
  id, source, name, singer, album, interval, picUrl
  musicInfo: MusicInfoOnline | null
  url?: string | null   // 新增：当前歌曲的音频直链，供网页版播放
}
```

- **取链**：`getPlayableUrl()` 调 `getMusicUrl({ isRefresh: false })`，同一首歌只请求一次，结果缓存 5 分钟（音源链接有时效，过期复用会 403），3 秒超时后降级为 `null`，不拖慢状态广播。
- **本地歌曲**：`source == 'local'` 直接返回 `null`，网页端无法访问 `file://`。
- **服务端**：只做字段透传，校验 `http(s)` 前缀与 4096 字符上限，音频流量不经过服务端。
- **网页端**：`<audio>` 直接加载直链，`loadedmetadata` 后按 `position + 延迟 × playRate` 对齐；播放/暂停/倍速/切歌都由 `state` 消息驱动，浏览器要求一次手势才允许出声，所以首次点击「同步收听」。
- **降级**：音源限制外链、链接失效或本地文件时，网页端把按钮置为「仅同步进度」并提示用 App 收听。

## 已知限制

- 只同步「当前播放的歌曲」，不同步播放列表/队列；成员的「下一首」由自己的列表决定，但会被房主状态覆盖。
- 本地歌曲依赖成员端能搜到同名在线歌曲，否则无法播放。
- 播放进度依赖设备系统时间计算，两端时间偏差过大时可能出现几秒的漂移。
- 房间统一音质只影响成员下一次取链接（切歌/重播），正在播的歌不会自动重载。
- 歌词以房主的为准；房主所在音源没有歌词时，成员回退使用自己的歌词。
- 网页版音频是各自拉流，起播时间有几百毫秒差异；音源限制外链时只能同步进度。
- App 被系统冻结后 WebSocket 可能断开，回到前台会自动重连，但期间不会跟随房主。
- 公网部署时服务端不提供 TLS，需要使用反向代理配置 `wss://`。
- iOS 对明文连接限制更严格：如果局域网 `ws://` 地址无法连接，请改用 `wss://`，或自行调整 `Info.plist` 的 ATS 配置。
